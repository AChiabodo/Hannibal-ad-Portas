# The external agent protocol is the Match's loop, asked over a pipe

An outside process plays a whole Match by being a **Player**: it is handed what its Faction may see — an Observation, fog and all — once per decision, and it answers with Commands from the closed vocabulary. The protocol is JSON Lines over that process's standard input and output, and it exposes exactly the projection the rules build for a Controller and nothing beside it: the three tile grids run-length encoded, the fog's raw contact list dropped in favour of the named one (`docs/PROTOCOL.md`). Everything that is not that is not the protocol: no state of the world outside the Faction's observation, no seed the Match has not told it, no wall clock.

To make that possible the loop that plays a Match is written once, as a sequence of **questions** — `matchQuestions` yields a Player and its Observation, and takes back that Player's answer — and it is *driven* two ways: `runMatch` asks a Controller and gets Commands in the same call, and `runMatchAsync` awaits an answerer that may be a process on the far end of a pipe. A question is a **Question** and not a "turn", because the glossary reserves that word for a Season's neighbours and this is not one (`GLOSSARY.md`, Season). The bound, the outcome, the copy of the Observation, the validation of what comes back and the log are the same code in both, because a Match is the loop and the rules and not a second, looser loop written for outsiders.

Three failures are a **Player who stopped playing**, and none of them is a failed run: a reply the vocabulary or the protocol cannot read, a reply that misses its deadline, and a process that exits. In each case the harness says `stopped` with the reason, stops asking, leaves that Faction idle, and plays the Match to its own end. The command exits 0, because a Match *was* played, and the report carries the verdict. The deadline is the one wall clock in the picture and it decides only whether the agent is still there: its reading never enters the world, the state or the hash, so a Match an agent timed out in replays as the Match its Command log describes.

**Considered Options**: making `Controller.decide` asynchronous — rejected because it changes the shape of the one seam for every Controller in the project, the human's and the AI's included, to serve the one implementation that needs to wait; the loop gained a second driver instead and the interface did not move. Reading the child's pipe with `fs.readSync` so a synchronous `decide` could block on it — rejected twice over: a blocking read cannot honour a deadline, and on Windows a libuv pipe handle has no file descriptor at all, so it is not portable. Serving the protocol on the harness's *own* standard input and output and letting whoever started it own the other end — rejected as the shipped default, because wiring two processes together bidirectionally is a shell trick (a fifo) rather than a command, and the harness already has to own the other Faction; the agent gets the pipes and the harness keeps the terminal. Asking for a decision on every tick — rejected as chatter: 25 200 observations of a quarter of a megabyte each, when silence is a legal answer and one decision a second is what a Player has time for. A reduced "agent API" with a summary of the world — rejected because the ticket's criterion is that the protocol exposes what the Faction can see and nothing more, and a summary would be a second projection to keep honest beside the first. Duplicating the driver's loop under `cli/` — rejected: the log's order, the bound and the verdict are what make a Match reproducible, and a second loop would drift from the first the first time either was edited.

**Consequences**: `sim/driver.ts` exports `matchQuestions`, `runMatchAsync` and the `Question` type, and `runMatch` is now three lines over the first of them, so the loop has one home. The protocol's own machinery — the messages, the wire form of an Observation, the reply reader — is pure and lives in `cli/protocol.ts`, where every refusal is a test; the process, the deadline and the spawn live in `cli/agent.ts`. `npm run agent` is the command, `--log` writes the Command log a replay is made of, and E2's replay tool reads that file. A stopped agent is a fact in the report (`status`, `stoppedBy`, `detail`) and not an exit code, so CI can run an agent whose answers it does not trust. `docs/PROTOCOL.md` is the document an agent is written from, `examples/agent.ts` is one written from it that imports nothing from this repository, and the test suite runs both the document's skeleton agent and the example to a result — a protocol nobody can implement from its own document is a protocol nobody has tested.
