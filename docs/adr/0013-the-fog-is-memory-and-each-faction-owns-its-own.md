# The fog is memory, and each Faction owns its own

The fog of war is per-Faction state, held as two grids each: the terrain as that Faction last saw it, and what it can see right now. A tile is *unexplored* where no eye has ever covered it, *remembered* where the ground was written down once and is out of view now, and *visible* where its Squads or settlements are looking. Vision is a disc of tiles by radius; there is no line of sight, because the theatre has no playable elevation (ADR-0007). Enemy contacts are remembered at the tile they were last observed standing on, with the tick they were seen, rather than tracked live. Because the memory decides what a Faction can decide, it is authoritative state: it is covered by the state hash, it is replayed like everything else, and it is never derived at the moment somebody looks. A projection built from the fog is plain structured-cloneable data, and the driver copies it, so a Controller can neither read past the fog nor write through it (ADR-0003). A debugging inspection mode exists that answers with the whole theatre known; it answers with a view, which has no `decide`, so it is not a Controller and cannot emit a Command.

**Considered Options**: a live mask recomputed each tick from what is visible now — rejected because a Faction that forgot the ground behind it could not plan a march, and because terrain memory is what makes a map worth scouting. Memory derived from the Match's history on demand rather than held as state — rejected because the history is the command log, not the knowledge, and a rule that asked for a tile's remembered ground would have to replay the Match to answer. One shared grid per Match with a per-Faction view of it — rejected because the first Faction's knowledge would then be inside the second's Observation and inside its part of the state hash, which is the whole of what partial observability is for. Storing `seen` as a flag beside the terrain grid — rejected because the two can disagree; one grid holding `UNSEEN` where nobody has looked answers both questions at once.

**Consequences**: a replay reproduces what each Faction knew, so a bug in an AI's reasoning is reproducible rather than reported. The state grows by two 9216-cell grids per Faction, which the hash walks every checkpoint — small next to the map itself, and the cost of partial observability being honest. Rules must refresh vision on every tick and are the only ones who can add or remove a contact, so the fog never forgets on its own; how long a stale contact is worth planning against is the AI's decision (D4). Anything that renders the fog renders the same object a Controller reads, which is the cheapest way for what a player sees and what a Player may decide to stay the same thing.
