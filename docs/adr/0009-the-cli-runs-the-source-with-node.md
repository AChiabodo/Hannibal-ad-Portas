# The headless CLI runs the TypeScript source directly

`npm run match` plays a whole Match with no build step, no bundler and no transpiler dependency: the script is `node src/cli/main.ts`, and Node strips the types as it loads the file. The simulation is plain TypeScript that never imports the engine (ADR-0001), so there is nothing in the way of running it exactly as written — and running the source the tests and the browser bundle are built from is what makes the CLI evidence rather than a parallel artifact.

Two consequences are deliberate. Every relative import under `src/` names its extension (`./command.ts`), because the module resolution in the standard requires it and Node does not guess the way a bundler does; Vite resolves both spellings, so the same source still builds for the browser. And `src/` stays erasable TypeScript — no `enum`, no `namespace`, no parameter properties — which `erasableSyntaxOnly` in the project's `tsconfig`s enforces, so a construct Node would have to generate code for fails `npm run check` rather than the command at runtime.

**Considered Options**: `tsx` — one dependency and no import-extension convention, rejected because it puts a package and roughly a third of a second of startup between an agent and every Match in a batch, on a project whose only runtime dependency is the renderer. Bundling the CLI with Vite or Rolldown into `dist/` — rejected because `npm run match` would then depend on a build having run, which is the step the headless core exists to avoid. A bespoke ESM loader that appends `.ts` to extensionless specifiers — rejected as a resolver that quietly guesses: the guards fail loudly on what they cannot see, and so should module resolution.

**Consequences**: the CLI starts in tens of milliseconds, which is what makes a hundred Matches a routine command. Node's type stripping does not type-check, so `npm run check` remains the only thing that does — and it is a required CI step already. A new module under `src/` that forgets its extension builds for the browser and fails at the command line, which the CLI's own subprocess tests catch. The project's minimum Node is 22.18, where stripping is enabled by default.
