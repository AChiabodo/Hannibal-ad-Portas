# A Squad of a single figure is drawn as one figure, and its strength is staying power

ADR-0004 already says that two kinds of entity are Squads of a single figure: war elephants and the siege ram. C4 had to decide what "a single figure" means against the numbers a Squad already has, because `SquadType.strength` was doing two jobs: it is what a Squad is **counted as** in a fight (C3 scales a blow by `frontage`, which is derived from strength) and it is what a Squad is **drawn as** (C2 composes one figure per man from `menOf`). An elephant at strength 1 would be drawn as one beast and killed by the first blow of any line; an elephant at strength 24 drawn the old way would be a block of twenty-four elephants.

So a Squad type may state a **`figures`**: how many figures a full-strength Squad of it is drawn as, defaulting to its `strength`. An elephant is `strength: 24, figures: 1`. `figuresOf(type)` is the only place the two are tied, the Observation carries both, and the split is exact: `strength` is a fact of the fight and never a fact of the drawing, and `figures` is a fact of the drawing and never a fact of the fight.

**Considered Options**: give an elephant strength 1 and a per-type combat weight, so that one figure could deal and take many men's worth of blows — rejected because it doubles the arithmetic of a round (ADR-0015 fixes the order of the chain and a test predicts it by hand) and adds a second damage currency to a model whose whole point is that a round moves two quantities. Draw the beast in a bigger box and keep one figure per man — rejected because the fixed figure box is what makes a block's sprite cheap and its anchor stable, and a per-type figure size would have to be threaded through the block, the picking rectangle and the corpse scatter. Special-case elephants inside `combat.ts` — rejected because the ticket's own out-of-scope says an elephant is "an ordinary Squad type with an extraordinary figure", and a second code path in the fight is how a model grows a third quantity.

**Consequences**: `figures` is content, so a drawing code (`render/squads.ts`, `render/game.ts`'s picking rectangle, the Atelier's plate) reads it where it used to read `men`; for every body-of-men type the two are the same number and nothing changes, so no existing drawing, hash or golden moved. Combat, the state hash and the roster's numbers are untouched. The siege ram, when C5 builds it, is the second type to state `figures: 1`, and it inherits the same reading for free.
